# Signed audit checkpoint format and verification

This document specifies the Android-generated `privacage-audit-checkpoint` JSON envelope (schema version 1) and the portable offline verifier in `shared/rust/pcage-audit`.

## What a successful verification proves

The verifier checks the exact embedded payload bytes against the signed SHA-256 digest, verifies an ECDSA signature using the embedded P-256 public key, validates the export schema and declared redactions, recomputes every event-chain link, and checks the final chain head and record count. It is read-only and makes no network requests.

A valid file proves only that the embedded public key signed the stated payload digest, chain head, event count and creation-time string. The public key is self-contained in the file, so **signature validity is not signer identity**. Compare the reported public-key fingerprint through a separate trusted channel before attributing the checkpoint to a device or person. The device clock can be wrong and events may have been omitted before export or never observed. The format is not encrypted.

## Envelope fields

The JSON object has exactly these fields; unknown and duplicate fields are rejected by the portable verifier.

| Field | Type | Requirement |
|---|---|---|
| `format` | string | `privacage-audit-checkpoint` |
| `schema_version` | integer | `1` |
| `signature_algorithm` | string | `SHA256withECDSA` |
| `created_at` | string | Canonical UTC instant generated by Java `Instant.toString()` |
| `signer_public_key_x509_base64` | string | Standard Base64 of DER SubjectPublicKeyInfo for a P-256 public key |
| `signer_public_key_sha256` | string | Lowercase SHA-256 hex digest of the decoded DER public-key bytes |
| `payload_sha256` | string | Lowercase SHA-256 hex digest of the exact UTF-8 bytes of `payload_json` |
| `chain_head_sha256` | string | Lowercase SHA-256 hex digest of the final event, or the genesis digest for an empty export |
| `event_count` | integer | Non-negative count equal to the payload count and integrity record count |
| `signature_base64` | string | Standard Base64 of a DER-encoded ECDSA signature |
| `payload_json` | string | The exact UTF-8 JSON text of the local audit export, stored as a JSON string |

The signed message is UTF-8 with LF separators and a final LF:

```text
PrivaCage-Audit-Checkpoint-v1
schema_version=1
signature_algorithm=SHA256withECDSA
created_at=<created_at>
payload_sha256=<payload_sha256>
chain_head_sha256=<chain_head_sha256>
event_count=<base-10 integer>
signer_public_key_sha256=<signer_public_key_sha256>
```

ECDSA uses SHA-256 and the P-256 / `secp256r1` curve. The DER public key is fingerprinted exactly as encoded; do not fingerprint the Base64 characters or a PEM wrapper.

## Event hash chain

The payload integrity object records `algorithm = sha256-chain-v1`, the all-zero 64-character `genesis_sha256`, `chain_head_sha256`, and `record_count`.

For each event, calculate SHA-256 over these bytes, in order:

1. ASCII `PrivaCage-Audit-Record-v1` and LF.
2. The previous record's 64-character lowercase hex digest and LF (the first previous digest is the genesis value).
3. For each UTF-8 field in this exact order — `timestamp`, `local_date`, `category`, `queried_hostname`, `socket_owner_label` — append the decimal UTF-8 byte length, ASCII colon, field bytes, then LF.

The resulting lowercase digest is `record_sha256`. The record's `previous_record_sha256` must equal the prior digest. The last digest must equal the checkpoint and payload chain heads. Hashing uses UTF-8 **byte lengths**, not character counts; do not normalize or re-serialize a field before hashing.

## Payload rules

The payload has schema version 1 and source `optional_local_dns_event_history`. Its only allowed event categories are `BLOCKED` and `FORWARDED`, and selected categories are unique and sorted. Every event must be in the inclusive declared date range and use a selected category. The counters must account for all stored records:

`records_read = records_skipped_invalid + records_excluded_by_filters + event_count`.

The permanent redaction claims for device identifiers, internal file paths and packet payloads must all be true. When `redactions.queried_hostnames` is true, every event hostname must be exactly `[REDACTED]`; the analogous rule applies to socket-owner labels. These checks prevent a payload from claiming that a field was redacted while including its raw value. They do not guarantee against every possible indirect identifier in a report.

## Bounds and compatibility

Schema-v1 verifiers reject checkpoints larger than 2 MiB, embedded payloads larger than 1 MiB, more than 100 events, overlarge encoded keys/signatures, invalid digests, unsupported key curves, extra or duplicate fields, inconsistent counters, malformed dates, inconsistent event hashes and incorrect signatures. The bounds match the current Android history limit and should not be raised casually.

Use:

```sh
cargo test --manifest-path shared/rust/pcage-audit/Cargo.toml
cargo clippy --manifest-path shared/rust/pcage-audit/Cargo.toml --all-targets -- -D warnings
cargo run --manifest-path shared/rust/pcage-audit/Cargo.toml -- path/to/checkpoint.json
```

The shared fixture in `shared/audit/test-vectors/checkpoint-v1.json` is a fixed test-only signature vector. Its private key is not included and must never be used in production. A schema change requires a versioned format change and updated interoperability tests.
