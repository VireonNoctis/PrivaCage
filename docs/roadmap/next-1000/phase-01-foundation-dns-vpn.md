# Phase 01 — Shared input integrity, Android DNS and VPN

**Milestones:** 221–320  
**Status rule:** all rows are planned acceptance targets unless explicitly marked otherwise. Passing unit tests do not replace required device, OS, operator or legal validation.

Milestone 221 records strict JSON input hardening already present on main, including duplicate-key rejection, byte and nesting limits, and invalid-Unicode rejection. Its verification status remains pending until the applicable Go workflow passes on a current code-bearing PR head. Remaining rows describe follow-up work, not current capabilities.

## Batch implementation notes (milestones 222–321)

The current batch extends tests and bounds across the existing Go tracker reader, Android bundled alternative-catalog loader, Kotlin DNS parser, DNS-over-TLS response validator, IPv4/IPv6 packet codecs, VPN session-status interpretation, local DNS history and APK DEX-string scanner. Rows marked **Implemented; CI pending** mean code and deterministic regression tests are present on the batch branch, not that CI or device-level acceptance has passed.

Where a target assumes cancellation, persistent transactions, or shared state in a pure parser/codec that has no such surface, the row is marked **Not applicable** with the reason instead of adding artificial state. Android VPN service lifecycle and saved-rule durability/concurrency remain explicit integration-test targets. No actual-device route, TLS resolver, Keystore, or OS behavior is claimed from host unit tests alone.
